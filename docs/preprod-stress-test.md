# Preprod stress test

This is a deliberate Midnight Preprod stress-test input set, not participant evidence. It creates 50 deterministic unshielded addresses and a stable plan reference for each slot. The addresses are valid testnet addresses, but the plan references are not transaction hashes until the faucet and wallet flow confirm them.

## Generate and check the plan

```bash
npm run pilot:wallets -- 50
npm run pilot:stress -- 50
```

The stress runner checks the Preprod faucet health endpoint and validates every address. The default mode is plan-only, so it does not submit requests.

## Execute faucet requests

For a one-address smoke test:

1. Open the [Midnight Preprod faucet](https://faucet.preprod.midnight.network/) and complete the Turnstile challenge.
2. Export the resulting token for this shell:

   ```bash
   export MIDNIGHT_CAPTCHA_TOKEN='<token from the live faucet widget>'
   ```

3. Run one explicit submission:

   ```bash
   npm run pilot:stress -- 1 --execute
   ```

For a batch stress test, collect one fresh Turnstile token per address into an untracked file (one token per line), then run:

```bash
MIDNIGHT_CAPTCHA_TOKENS_FILE=/path/to/tokens.txt npm run pilot:stress -- 50 --execute
```

Turnstile tokens are single-use; do not reuse one token across the batch.

The runner records confirmed faucet transaction hashes in the `transaction_reference` column of [`docs/pilot-transaction-proof.csv`](./pilot-transaction-proof.csv), preserving the original `plan_reference`. Failed or timed-out slots remain marked `FAILED` and should be retried individually. Do not fund these deterministic keys beyond testnet use; the generator intentionally keeps the stress-test secrets reproducible for repeatable runs.

## Fund destinations from slot 01

Slot 01 is the funded source wallet. Its canonical faucet transaction and DUST-registration transaction are listed in [`preprod-source-funding.md`](./preprod-source-funding.md). The fee-paying wallet path is:

```bash
npm run pilot:dust-sync
npm run pilot:stress -- 50 --execute --fund-children
```

`pilot:dust-sync` replays the public DUST ledger into `.proofroom-cache/` (ignored by git). `--fund-children` submits 49 serial unshielded transfers through the Preprod RPC and waits for each destination output to appear as `SUCCESS` in the indexer. The CSV is updated after every confirmed transfer, so an interrupted run can resume.

After the run, independently verify every hash against its indexed output and persist block references:

```bash
npm run pilot:verify
```

The proof CSV then includes `block_height`, `block_hash`, and `amount_raw` for every confirmed row.

## ProofRoom application calls

After funding, the same 50 slots were used as distinct Compact callers. The deployed contract is recorded in [`proofroom-preprod-deployment.json`](./proofroom-preprod-deployment.json). Run the reproducible batch (slot 01 is already present and slots 02–50 are idempotently skipped when confirmed):

```bash
PROOFROOM_APP_FROM=1 PROOFROOM_APP_TO=50 npm run pilot:app:all
npm run pilot:verify-app
```

The application register [`preprod-application-transactions.csv`](./preprod-application-transactions.csv) contains 50 real `createListing` `SUCCESS` receipts. Slot 01 sponsors DUST fees for slots 02–50; each caller remains a separate wallet address in the register. The verifier matches tx ID, contract action address, status, block, timestamp, and indexer ID against the public GraphQL indexer.
