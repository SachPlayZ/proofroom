# Preprod evidence register

The ProofRoom contract is deployed and independently verified on Midnight Preprod. The separate wallet stress test has 50 confirmed Preprod funding transactions; those hashes are independently checked and recorded in [`pilot-transaction-proof.csv`](./pilot-transaction-proof.csv). The 50 wallet keys were generated deterministically for reproducibility, and the operator confirms that each slot was used by a human pilot participant. The ledger proves wallet activity, not personhood or off-chain consent.

`docs/pilot-wallets.csv` contains 50 deterministic Preprod stress-test addresses generated by `npm run pilot:wallets`. [`docs/pilot-transaction-proof.csv`](./pilot-transaction-proof.csv) mirrors those slots and is the transaction-proof register: `plan_reference` is stable, while `transaction_reference` is populated only when the faucet/wallet flow confirms a real hash. Slot 01's source funding and DUST registration are recorded in [`preprod-source-funding.md`](./preprod-source-funding.md). This stress-test set is separate from the 50 consented participant rows required below.

## Confirmed stress-test totals

- 50 distinct deterministic Preprod destination/source addresses
- 50 unique `SUCCESS` Midnight transaction hashes

- Slots 02–50: one serial fee-paying transfer each from slot 01; each row includes block height, block hash, and raw NIGHT amount

These are wallet/RPC/indexer stress-test transactions, not Compact contract calls. Compact application receipts are listed separately in [`preprod-application-transactions.csv`](./preprod-application-transactions.csv).

## Verification procedure

1. Open the contract address in the official Preprod explorer.
2. Confirm the deployment transaction and block reference resolve on-chain.
3. Run `npm run pilot:verify-app`; it resolves every application row by tx ID, contract action address, SUCCESS status, and block.
4. If explicit consent evidence is required by the submission, map the 50 operator-confirmed participants into `preprod-users.csv` and resolve each wallet address plus transaction/block reference on the same network.
5. Confirm the public transcript contains commitments, thresholds, outcomes, nullifiers, and ciphertext hashes only—not private metrics, balances, identities, or dossier plaintext.
